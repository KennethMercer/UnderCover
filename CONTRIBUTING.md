# Contributing to UnderCover

A few house rules first. Most of them were paid for, some with somebody's data.

## Read before you touch anything

1. [docs/MASTERPLAN.md](docs/MASTERPLAN.md): what UnderCover is for and how decisions get made.
2. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): the names, the layout, the dependency rules, the data contracts and the
   engine choices.
3. The code you're changing, and the checks around it in `tests/smoke.py`.

If the docs seem wrong for the problem in front of you, say so in your pull request and make the case. The vision is
allowed to grow, just not by accident.

## The rules that don't bend

**Tests never reach real data.** A test that creates, moves or deletes files gets its own temp folders and its own
minimal config (`isolated_data()` in `tests/smoke.py`), never a copy of someone's `config.toml`. Code that deletes or
moves user files goes through `core/storage.py`'s allow-list, which refuses the real folders in test mode. A pull
request that can reach a user's `uploads/`, `output/`, `models/` or `cache/` from a test will not be merged, however
good it is. On 2026-10-11 a check that wasn't isolated deleted the maintainer's songs and covers.

**User data is sacred.** Voices, projects, songs, covers and speech are hours of someone's work and often a real
person's likeness. Nothing automatic deletes them except the rules the user set, through the guarded path, one item
at a time.

**Pinned, verified, reproducible.** Every package has an exact version and a hash (`installer/requirements/*.txt`,
generated by `installer/pin_hashes.py`); every downloaded file has a pinned version and a SHA-256
(`installer/downloads.tsv`). Installs always run with `-c installer/constraints.txt`. "latest" is never a version.
A pin moves only after `tests/smoke.py --full` passes on the new one.

**It has to run on AMD on Windows.** No CUDA-only libraries, no Triton, no `torch.compile`. NVIDIA and CPU builds
must keep working too. Windows-only calls go through `core/platform.py`, so a Linux version stays possible.

**The module boundaries** (`tests/smoke.py` checks them):
- `core` imports no module.
- Modules import `core`. FrontMan and SpeakEasy reach DoubleAgent only through `doubleagent.service`, never each
  other.
- Only `app` imports `safehouse`. Nothing imports `app`.

**Licences restrict distribution, not quality.** A new engine or model whose code and weights are under an OSI
licence can be included. Anything else (non-commercial, research-only, custom) goes in as an add-on in
`core/addons.py`, never installed without the user ticking "I accept", and the app must keep working on its open
default without it. With no licence at all: open an issue first. Add the part to NOTICE in the same pull request.

**The ear decides.** Measurements guide; they don't rule. A change to how voices or references are picked comes with
listening samples, and a voice the user approved by ear is never replaced by a score alone.

**Simple by default.** New screens are designed basic-first. Expert-only elements carry `data-deep` from the day
they're built, so Deep Cover can hide them.

**Keep the names and the voice.** FrontMan, DoubleAgent, SpeakEasy, SafeHouse, Deep Cover, rooms. Copy is plain and
a little spy-noir: short sentences, no jargon on the basic view, never cute at the user's expense.

## What never goes in the repository

- Real people's voices or recordings: no voice models, clips, references, A/B samples, covers or speech of a real
  person, and no links to the sources of one. Test with your own voice locally, and keep it out of git.
- Copyrighted songs, even short clips.
- Secrets, tokens, cookies, personal paths, your home-network address.
- Pickled model formats in anything new: shared or new formats are safetensors + JSON (a `.pth` can run code).

`.gitignore` already keeps the data folders out. Check `git status` before you commit.

## Running the checks

```
.venv\Scripts\python.exe tests\smoke.py --unit-only     # about a minute, no server
.venv\Scripts\python.exe tests\smoke.py                 # + API, one cover, one speech (a few minutes)
.venv\Scripts\python.exe tests\smoke.py --full          # + a short training with Pause/Resume, cadence (10-25 min)
```

The end-to-end checks start their own sandbox server on the first free port of 7862-7869, with scratch folders, and
fail if any real folder changed during the run. Port 7860 is the user's own server: never start or stop it from a
test. Tests that play audio must mute the page first.

Known gap: `--full` copies one installed voice and its training project into the sandbox, so it needs a trained
voice on your PC. A small synthetic test voice is planned.

## Making a change

1. Open an issue first for anything bigger than a fix, so nobody builds something a planned phase will move.
2. Branch from `main`. One logical change per commit.
3. Files are CRLF; keep them that way. Windows paths in Python go through `pathlib`.
4. Run `tests\smoke.py --full` before you ask for a review, and say what you measured and what you skipped. A review
   that found nothing says "nothing".
5. Sign off your commits (`git commit -s`). That certifies the
   [Developer Certificate of Origin](https://developercertificate.org/): you wrote the change, or have the right to
   submit it under the project's licence.
6. Anything that deletes or moves user files gets read line by line by a maintainer, whatever the tests say.

## Conduct

Be straight, be kind, and remember that real people's voices are involved. Harassment, or using the project's spaces
to share someone's cloned voice without their consent, gets you removed.
